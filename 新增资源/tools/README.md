# 新增资源批处理

保留本机旧库 SQLite 作为只读输入。仓库中仅保存自主制作或可再分发的成果、来源许可和增量元数据。

- 图表生成命令为 `node 新增资源/tools/charts.cjs <暂存目录>`，依赖 pptxgenjs。只在暂存目录重跑，避免覆盖已提交的 PPTX。使用 LibreOffice 或 PowerPoint 渲染并复核各页。渲染失败先修正生成器。
- 配色生成命令为 `python3 新增资源/tools/palettes.py <上游快照目录> <暂存目录>`。快照目录需要 ColorBrewer 官方仓库固定版本的 `colorbrewer_schemes.js`、`LICENCE.txt` 和纯文本 `revision`。本批固定提交见批次 NOTICE。
- 审核后的暂存目录需要 `资源描述.json`，格式参见已发布批次。将目录置于 `新增资源/batch-NNN`，运行 `python3 新增资源/tools/finalize.py 新增资源 NNN <本机旧库索引.sqlite>`。只对下一批运行。脚本复用查重脚本，同时比对旧库、累计增量和批内素材，核对文件及校验值。视觉疑似项与内容提示须人工复核。
- 成功后用 `git add -- 新增资源 && git commit -m "Add batch NNN" && git push origin main` 提交，再进入任务状态文件记录的下一批。若提交已生成且推送失败，直接重试推送。若索引已生成且尚未提交，先核对暂存内容再提交，避免重跑生成覆盖已验收内容。

累计索引路径相对 `新增资源`，单批索引路径相对该批目录。跨库视觉复核与原导入程序兼容性单独记录。

- 材质和装饰命令为 `python3 新增资源/tools/textures.py <暂存目录>`。该批生成原生 SVG 素材。渲染审阅全批，核对画布、图层和透明背景后执行入库。
- 下一批编号 005。先准备字体与页面版式候选，逐项核对字体分发许可及是否允许随素材再分发。按相同描述格式保存资源；加入新格式时先明确格式验证，再运行入库流程。旧库索引继续作为本机参数。
